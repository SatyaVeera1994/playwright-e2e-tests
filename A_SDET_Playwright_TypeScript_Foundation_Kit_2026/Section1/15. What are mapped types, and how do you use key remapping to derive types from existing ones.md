# Q15. What are mapped types, and how do you use key remapping to derive types from existing ones?

**Level: Senior**

This is an important advanced TypeScript topic because it shows that you know how to **derive types instead of duplicating them**.

---

## ✅ 1. English Interview Answer

> **“A mapped type creates a new type by iterating over the keys of an existing type and transforming the keys, values, or both. The basic syntax is `{ [K in keyof T]: ... }`. TypeScript utility types such as `Partial`, `Required`, `Readonly`, `Pick`, and `Omit` are based on this concept. With key remapping, introduced in TypeScript 4.1, we can use `as` to rename keys while mapping them. In an SDET framework, I can use this to derive typed Page Object getters, builder APIs, or mock interfaces from a single source-of-truth interface. The main principle is: derive types, don't duplicate them.”**

### ⭐ Short Interview Answer

> **“Mapped types transform an existing type by iterating over its keys, and key remapping allows us to rename those keys. This helps us derive framework types automatically instead of duplicating interfaces.”**

# 🔍 3. Internal Concept — How Mapped Types Work

Suppose we have:

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  isAdmin: boolean;
}
```

Think of:

```typescript
keyof User
```

as:

```text
"id" | "name" | "email" | "isAdmin"
```

Now:

```typescript
type UserCopy = {
  [K in keyof User]: User[K];
};
```

TypeScript internally goes through each key:

```text
id       → User["id"]       → string
name     → User["name"]     → string
email    → User["email"]    → string
isAdmin  → User["isAdmin"]  → boolean
```

Result:

```typescript
interface UserCopy {
  id: string;
  name: string;
  email: string;
  isAdmin: boolean;
}
```

# 🧩 4. Basic Mapped Type Example

### Make everything optional

```typescript
type PartialUser = {
  [K in keyof User]?: User[K];
};
```

This becomes:

```typescript
type PartialUser = {
  id?: string;
  name?: string;
  email?: string;
  isAdmin?: boolean;
};
```

That's basically the idea behind:

```typescript
Partial<User>;
```

---

### Make everything readonly

```typescript
type ReadonlyUser = {
  readonly [K in keyof User]: User[K];
};
```

Now:

```typescript
const user: ReadonlyUser = {
  id: "u123",
  name: "Satya",
  email: "satya@test.com",
  isAdmin: false,
};
```

This is conceptually what:

```typescript
Readonly<User>;
```

does.

# 🔥 5. Key Remapping

Now comes the **Senior-level part**.

We don't just want the same keys.

Suppose:

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  isAdmin: boolean;
}
```

We want:

```text
getId()
getName()
getEmail()
getIsAdmin()
```

Instead of manually writing:

```typescript
interface UserGetters {
  getId(): Promise<string>;
  getName(): Promise<string>;
  getEmail(): Promise<string>;
  getIsAdmin(): Promise<boolean>;
}
```

We can derive it automatically.

---

# 💻 6. Key Remapping Code

```typescript
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => Promise<T[K]>;
};
```

Then:

```typescript
type UserGetters = Getters<User>;
```

TypeScript generates:

```typescript
interface UserGetters {
  getId(): Promise<string>;
  getName(): Promise<string>;
  getEmail(): Promise<string>;
  getIsAdmin(): Promise<boolean>;
}
```

---

# 🔍 Understand This Syntax

The important part is:

```typescript
[K in keyof T]
```

means:

> **“Loop through every key in T.”**

Then:

```typescript
as`get${Capitalize<string & K>}`;
```

means:

> **“Rename each key by adding `get` and capitalizing it.”**

For example:

```text
id
 ↓
Id
 ↓
getId
```

And:

```text
email
 ↓
Email
 ↓
getEmail
```

---

# 💼 7. Real-Time SDET / Playwright Example

This is where you should make your answer practical.

Imagine your framework has a domain model:

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  isAdmin: boolean;
}
```

Your Page Object needs getter methods.

Instead of manually maintaining:

```typescript
getId();
getName();
getEmail();
getIsAdmin();
```

we derive the type:

```typescript
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => Promise<T[K]>;
};
```

Then:

```typescript
type UserGetters = Getters<User>;
```

---

## Playwright-style implementation

```typescript
class UserPage {
  async getId(): Promise<string> {
    return await this.page.locator('[data-test="user-id"]').innerText();
  }

  async getName(): Promise<string> {
    return await this.page.locator('[data-test="user-name"]').innerText();
  }

  async getEmail(): Promise<string> {
    return await this.page.locator('[data-test="user-email"]').innerText();
  }

  async getIsAdmin(): Promise<boolean> {
    return await this.page.locator('[data-test="admin"]').isChecked();
  }
}
```

The **interface contract** can be derived automatically:

```typescript
type UserGetters = Getters<User>;
```

So if later we change:

```typescript
interface User {
  id: string;
  name: string;
  email: string;
  isAdmin: boolean;
  phone: string;
}
```

The derived type automatically expects:

```text
getPhone()
```

# 🎯 Why Is This Useful?

Imagine you manually created 20 interfaces.

```text
User
UserGetters
UserBuilder
UserMock
UserDTO
UserRequest
```

If `User` changes, you have to remember to update all of them.

That's dangerous.

With mapped types:

```text
             User
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   Getters  Builder   Mock
```

One source of truth.

### ⭐ Senior principle:

> **“Derive, don't duplicate.”**

# 🧠 8. Utility Types Are Based on This Idea

Interviewers may ask:

**“Are `Partial`, `Readonly`, `Required`, etc. mapped types?”**

### Answer:

**Yes.**

Conceptually:

```typescript
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};
```

Equivalent idea:

```typescript
Partial<User>;
```

---

### MyReadonly

```typescript
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

---

### Required

```typescript
type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};
```

The `-?` removes the optional modifier.

# 🎯 9. Follow-up Questions Interviewers May Ask

## Q1. What is a mapped type?

> **“A mapped type iterates over the keys of an existing type using `keyof` and creates a transformed type.”**

---

## Q2. What does `keyof` do?

> **“`keyof` produces a union of the property names of a type.”**

Example:

```typescript
interface User {
  id: string;
  name: string;
}
```

```typescript
type UserKeys = keyof User;
```

Result:

```typescript
"id" | "name";
```

---

## Q3. What is key remapping?

> **“Key remapping allows us to rename mapped keys using the `as` clause.”**

Example:

```typescript
[K in keyof T as `get${Capitalize<string & K>}`]
```

---

## Q4. Since which TypeScript version is key remapping available?

> **“Key remapping with `as` was introduced in TypeScript 4.1.”**

---

## Q5. Give a real framework use case.

⭐ Best answer:

> **“I can derive Page Object getter interfaces from domain models, generate builder methods from entity types, or derive typed mock functions from service interfaces.”**

---

## Q6. What happens if the original interface changes?

> **“The mapped type automatically reflects the change, which keeps the derived type synchronized with the source type.”**

This is one of the strongest points to mention.

---

## Q7. Why is duplication a problem?

> **“Manually duplicated interfaces can drift apart. The source type may change while the derived interface remains outdated, causing the test framework's types to lie about the actual application.”**

# 🧠 11. Easy Memory Trick

Remember:

## **KEY → LOOP → TRANSFORM → RENAME**

### 1. KEY

```typescript
keyof T
```

Get the keys.

### 2. LOOP

```typescript
[K in keyof T]
```

Loop through them.

### 3. TRANSFORM

```typescript
T[K];
```

Transform the value type.

### 4. RENAME

```typescript
as `get${...}`
```

Rename the key.

> **“Mapped type = Loop through keys and transform them.”**
