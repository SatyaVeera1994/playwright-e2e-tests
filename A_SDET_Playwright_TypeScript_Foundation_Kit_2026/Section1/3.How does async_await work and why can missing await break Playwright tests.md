# Q3. How does `async/await` work, and why can missing `await` break Playwright tests?

## ✅ English Interview Answer

> **“Playwright operations such as `goto()`, `click()`, `fill()`, and API calls are asynchronous and return Promises. I use `async/await` to wait for these operations to complete before moving to the next step. If I miss `await`, the next statement may execute before the previous operation finishes, which can cause race conditions and flaky tests.”**

### ⭐ Short interview answer

> **“`async` makes a function return a Promise, and `await` waits for a Promise to complete before continuing execution.”**

# 🔍 Internal Concept — How it works internally

Suppose we have:

```typescript
await page.goto("/login");
await page.getByLabel("Username").fill("admin");
await page.getByRole("button", { name: "Login" }).click();
```

Internally, conceptually:

```text
page.goto()
    ↓
Promise created
    ↓
await
    ↓
Navigation completes
    ↓
Next statement
    ↓
fill()
    ↓
Promise
    ↓
await
    ↓
Next statement
```

`await` doesn't mean Playwright stops the entire program. It pauses the **current async function** until the Promise settles, allowing JavaScript's asynchronous execution model to continue handling other work.

# ❌ What happens if `await` is missing?

```typescript
test("Login", async ({ page }) => {
  page.goto("/login");

  page.getByLabel("Username").fill("admin");

  page
    .getByRole("button", {
      name: "Login",
    })
    .click();
});
```

Here we didn't await the operations.

Execution can become unpredictable:

```text
goto starts
   ↓
fill starts
   ↓
click starts
   ↓
navigation may not be completed ❌
```

This can produce:

- Race conditions
- Flaky tests
- Actions happening in the wrong order
- Unexpected failures

# 💻 Important Real-Time Example — API + UI

Suppose clicking **Login** triggers:

```text
POST /api/login
```

We want to capture the response.

### Correct approach

```typescript
test("Validate login API", async ({ page }) => {
  const [response] = await Promise.all([
    page.waitForResponse("**/api/login"),

    page
      .getByRole("button", {
        name: "Login",
      })
      .click(),
  ]);

  expect(response.status()).toBe(200);
});
```

### Why `Promise.all()`?

Because we need to:

```text
Start listening for response
        +
Click Login
        ↓
Wait for both
        ↓
Get response
```

The important point is to establish the response listener **before** the action that triggers the request. The Foundation Kit specifically emphasizes this ordering for `waitForResponse()`.

# 🎯 Follow-up Questions Interviewer May Ask

### Q1. What is `async`?

> **`async` makes a function return a Promise and allows us to use `await` inside that function.**

---

### Q2. What is `await`?

> **`await` pauses the current async function until the Promise is settled.**

---

### Q3. What happens if you forget `await`?

> **The operation may continue asynchronously while the next statement executes, potentially causing race conditions or flaky tests.**

---

### Q4. Does `await` make JavaScript synchronous?

> **No. It only makes asynchronous code easier to read and execute in a sequential-looking manner. JavaScript remains asynchronous underneath.**

---

### Q5. Why use `Promise.all()` in Playwright?

> **To coordinate multiple asynchronous operations, especially when one operation triggers another, such as clicking a button and waiting for the corresponding API response.**

---

### Q6. Why should `waitForResponse()` come before the click?

> **Because the click triggers the network request. If the listener starts too late, we may miss the response.**

---

### Q7. Which Playwright methods commonly require `await`?

Examples:

```typescript
await page.goto();

await page.click();

await page.fill();

await locator.textContent();

await expect(locator).toBeVisible();
```

### 🎯 Best 15-second interview answer

> **“Playwright APIs are asynchronous and return Promises. I use `async/await` to maintain the correct execution sequence. Missing `await` can create race conditions and flaky tests. For dependent asynchronous operations, such as clicking a button and capturing its API response, I use `Promise.all()` with the response listener registered before the triggering action.”**
