## How Do You Handle Test Flakiness in Playwright?\*\*

## I handle test flakiness by identifying the root cause of inconsistent test failures. I use reliable locators, Playwright auto-waiting, and proper assertions. I avoid unnecessary fixed waits and handle network delays properly. I also use retries for temporary failures and Trace Viewer, screenshots, and videos to debug failed tests. Finally, I fix the root cause instead of depending only on retries.

## 3. Common Causes of Flaky Tests\*\*

| Reason                       | Solution                    |
| ---------------------------- | --------------------------- |
| Unstable locators            | Use reliable locators       |
| Element loading delay        | Use auto-waiting            |
| API response delay           | Wait for expected response  |
| Fixed timeout                | Use proper assertions       |
| Test dependency              | Make tests independent      |
| Parallel execution conflicts | Use separate test data      |
| Environment issues           | Check environment stability |

## **4. Important Interview Follow-up**

**Q: What is the difference between flaky tests and failed tests?**

- Failed test: Test consistently fails because of a defect or incorrect expectation.
- Flaky test: Test sometimes passes and sometimes fails without a consistent result.

## **1. How do you handle flaky tests?**

### **1. Use Auto-Waiting**

Playwright automatically waits for elements to become actionable before performing actions.

```
await page.getByRole('button', { name: 'Login' }).click();
```

Unnecessary fixed waits avoid cheyyali.

```
// Avoid
await page.waitForTimeout(5000);
```

### **2. Use Proper Locators**

Use reliable locators like `getByRole()`, `getByLabel()` and `getByTestId()`.

```
await page.getByTestId('login-button').click();
```

Dynamic or unstable XPath locators avoid cheyyali.

### **3. Use Proper Assertions**

Use Playwright's auto-retrying assertions.

```
await expect(page.locator('.success-message'))
  .toBeVisible();
```

Assertion condition satisfy ayye varaku Playwright wait chestundi (up to the configured timeout).

### **4. Handle Network Issues**

Sometimes API response delay valla tests fail avvachu.

```
await page.waitForResponse(response =>
  response.url().includes('/api/users') &&
  response.status() === 200
);
```

### **5. Use Retry Mechanism**

Playwright lo retries configure cheyochu.

```
export default defineConfig({
  retries: 2,
});
```

Test fail ayithe Playwright maximum 2 retries chestundi.

**Important:** Retries are useful for identifying flaky tests, but they do not fix the actual root cause.

### **6. Debug Using Trace Viewer**

Trace Viewer use chesi test failure reason identify cheyochu.

```
export default defineConfig({
  use: {
    trace: 'retain-on-failure',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
});
```

Trace, screenshot and video help us understand what happened during execution.
