# Q4. What are TypeScript Generics and how do you use them in a Playwright framework?

The Foundation Kit describes generics as a way for a function or class to work with a **type supplied by the caller while maintaining full type safety**. Its key SDET examples are a **typed API client** and a **test-data factory**.

---

## ✅ English Interview Answer

> **“Generics allow us to create reusable functions or classes that can work with different data types while maintaining type safety. In a Playwright framework, I mainly use generics for typed API clients and test-data factories. For example, I can create one generic API method and specify the expected response type at the calling point instead of creating a separate method for every response.”**

# 🔍 Internal Concept — How Generics Work

Suppose we have a normal function:

```typescript
function getData(data: any) {
  return data;
}
```

Problem:

`any` use chesthe type safety pothundi.

Instead:

```typescript
function getData<T>(data: T): T {
  return data;
}
```

Here:

```text
T = Type placeholder
```

Calling time lo actual type provide chestam.

```typescript
const name = getData<string>("Satya");

const age = getData<number>(30);
```

So internally:

```text
getData<string>()
       ↓
T becomes string

getData<number>()
       ↓
T becomes number
```

# 💼 Real-Time SDET Example — Generic API Client

This is one of the most important real-world uses from the Foundation Kit.

Suppose our application has:

```text
GET /users/1
GET /orders/101
GET /products/10
```

Each API returns a different response.

Instead of writing:

```typescript
getUser();
getOrder();
getProduct();
```

we can create **one generic API method**.

---

# 💻 Code — Generic API Client

```typescript
import { APIRequestContext } from "@playwright/test";

async function apiGet<T>(request: APIRequestContext, url: string): Promise<T> {
  const response = await request.get(url);

  if (!response.ok()) {
    throw new Error(`API failed: ${response.status()}`);
  }

  return (await response.json()) as T;
}
```

Now define response types:

```typescript
interface User {
  id: number;
  name: string;
  email: string;
}

interface Order {
  id: number;
  amount: number;
  status: string;
}
```

Use the **same function**:

```typescript
const user = await apiGet<User>(request, "/api/users/1");

console.log(user.name);
```

For order:

```typescript
const order = await apiGet<Order>(request, "/api/orders/101");

console.log(order.amount);
```

### What happened?

```text
             apiGet<T>()
                │
        ┌───────┴────────┐
        ↓                ↓
    User type        Order type
        ↓                ↓
   User response    Order response
```

One reusable function.

Different response types.

**Type safety maintained.**

# 💼 Second Real-Time Example — Test Data Factory

Generics test-data factories ki kuda useful. The Foundation Kit specifically describes a factory that accepts defaults and optional partial overrides while returning the same type.

```typescript
function createTestData<T>(defaults: T, overrides?: Partial<T>): T {
  return {
    ...defaults,
    ...overrides,
  };
}
```

Define user:

```typescript
interface User {
  name: string;
  email: string;
  role: string;
}
```

Create default data:

```typescript
const user = createTestData<User>(
  {
    name: "Test User",
    email: "test@test.com",
    role: "user",
  },
  {
    role: "admin",
  },
);
```

Result:

```text
name  → Test User
email → test@test.com
role  → admin
```

### 🇮🇳 Telugu

Default test data:

```text
name = Test User
email = test@test.com
role = user
```

Specific test case lo role matrame change cheyyali:

```typescript
{
  role: "admin";
}
```

`Partial<T>` valla migatha fields mandatory ga ivvalsina avasaram ledu.

# 🎯 Follow-up Questions Interviewer May Ask

### Q1. Why not use `any` instead of generics?

**Answer:**

> “`any` removes type safety, whereas generics preserve the relationship between the input and output types.”

### Telugu

`any` → type checking almost remove chestundi.

`Generic` → type safety maintain chestundi.

---

### Q2. What does `<T>` mean?

**Answer:**

> “`T` is a conventional name for a generic type parameter. It acts as a placeholder for the actual type supplied by the caller.”

### Telugu

`T` = **Type placeholder**.

---

### Q3. Can we have multiple generic parameters?

Yes.

```typescript
function merge<T, U>(first: T, second: U): T & U {
  return {
    ...first,
    ...second,
  };
}
```

Usage:

```typescript
const result = merge({ name: "Satya" }, { age: 30 });
```

---

### Q4. Where do you use generics in your automation framework?

### Strong answer:

> **“I mainly use generics in typed API clients and test-data factories. For API clients, the caller specifies the expected response type, so the same method supports multiple endpoints. For test-data factories, generics allow the factory to return the same type as the input while supporting partial overrides.”**

This directly matches the framework-oriented use cases in the source.

---

### Q5. What happens if an API response type changes?

**Answer:**

> “The typed call sites can expose compile-time errors or incorrect assumptions, allowing us to update the affected tests before discovering the problem only during runtime.”
