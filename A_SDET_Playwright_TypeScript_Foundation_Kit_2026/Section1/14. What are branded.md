# Q14. What are branded (nominal) types and how do they prevent ID-mixup bugs?

## ✅ 1. English Interview Answer

> **“TypeScript is structurally typed, so two values with the same shape are normally interchangeable. This can be dangerous for domain IDs because `UserId` and `OrderId` may both be strings. # 🔍 3. Internal Concept — How It Works

First understand **structural typing**.

Normally:

```typescript
type UserId = string;
type OrderId = string;
```

TypeScript sees:

```text
UserId → string
OrderId → string
```

So:

```typescript
function deleteOrder(id: OrderId) {
  // delete order
}

const userId: UserId = "u_123";

deleteOrder(userId); // ❌ We WANT an error, but TypeScript allows it
```

Why?

Because both are structurally just:

```text
string
```

---

# 🔐 Branded Types Solve This

We add a phantom discriminator:

```typescript
type UserId = string & { readonly __brand: "UserId" };

type OrderId = string & { readonly __brand: "OrderId" };
```

Now TypeScript sees:

```text
UserId
  ↓
string + UserId brand

OrderId
  ↓
string + OrderId brand
```

Therefore:

```text
UserId ≠ OrderId
```

at compile time.

# 🎯 9. Follow-up Questions

### Q1. Why are `UserId` and `OrderId` interchangeable without branding?

**Answer:**

> “Because TypeScript uses structural typing, and both are structurally just `string`.”

---

### Q2. What does the brand actually do?

> **“It adds a phantom discriminator at the type level, making otherwise identical types incompatible.”**

---

### Q3. Is the brand available at runtime?

> **“No. It exists only in the TypeScript type system.”**

---

### Q4. Does branding validate that the ID is actually valid?

Important distinction:

> **“No. Branding provides compile-time distinction, not runtime validation.”**

For example:

```typescript
const userId = UserId("anything");
```

The brand doesn't prove that `'anything'` is a real user ID.

If you need runtime validation, you need additional validation.

⭐ Strong answer:

> **“TypeScript is fundamentally structurally typed, but branded types provide a practical form of nominal typing by adding a unique compile-time marker.”**
